Final bounded qualification is recorded in `../STAGE4-REPORT.md` and `../inventory/stage4-targets.json`; earlier worker-status notes describe their historical snapshot.

The target is a public-API consumer of the actual `peritus-journal` SQLite adapter. ## Independent truth and operation histories

An append-only event list and exact original-command packets provide expected global positions, aggregate sequences, predecessor identities, fixed revision bindings, raw frame bytes, state revisions and historical values. Inputs are synthetic one-byte payloads; alternating registered frame families expose misrouting. Expected event, batch and head hashes use explicit documented domain/preimage fields over those inputs and ordinary SHA-256, never the production hash-chain helpers or verified predicates. This is binary-format correspondence, not a cryptographic collision-resistance proof.

Aggregate heads are opaque public values with no public constructor. The consumer independently checks their identity, sequence, event ID and hash against the event list before using them as CAS handles. State and event expectations never come from production replay. Original packets remain available for exact duplicate replay after later heads/state have advanced; command identity with a changed request digest must reject. The public append contract binds the caller-supplied digest, so the campaign does not invent a promise that C0 independently decodes arbitrary application intent.

Generated histories interleave fresh same-connection and peer commits, original/conflicting retries, saved replay observations, guarded appends, stale aggregate/state CAS, another-store plans, real competing SQLite writer locks, an injected real SQLite trigger failure after event/state/outbox insertion but before command-row completion, invalid pre-append plans, unrelated external SQLite commits, actual close/reopen, and outbox claim/acknowledgement. Each recognized rejection is followed by exact event/state/history/outbox readback and continued real operations. Constructor/plan rejection is not an append attempt and must leave replay observations current; every actual append attempt invalidates older observations even when it fails or replays. Same-connection mutable outbox operations are explicitly outside ReplayObservation's append-owned guarantee.

The real trigger/lock paths operate only in the disposable database. They do not substitute a fake storage implementation. Atomicity means no committed event, state-history, command receipt or outbox row leaks through the failed transaction. Each aggregate's next uncommitted historical revision is explicitly queried as absent, in addition to checking every expected revision and current state. Accepted/replayed receipts must contain exactly the expected records and affected heads, with exact input-derived values, rather than merely pointing at correct durable rows. This does not qualify arbitrary OS write/fsync failures or power-loss durability.

The generated/fixed `AtomicBatch` wave adds a two-aggregate, two-event, two-state and two-outbox interaction. Its actual SQLite trigger raises only on the second frame family when the transaction already contains exactly one event; the observed source error and append operation must identify that exact trigger boundary. Failed append must leave both aggregates, both current/historical state rows, both outbox rows and command resolution absent. Removing the fault and continuing the identical request must commit global positions one/two, independently expected event/batch hashes and both state/outbox producers at the final batch position. Exact replay must return the original receipt, a changed request digest must conflict, and real reopen must preserve the whole batch. This distinguishes partial second-row rollback from the ordinary single-event histories.

## Outbox lease model and confirmed defect

The delivery model owns creation position, exact bytes/destination, attempts, maximum attempts, claim fence and lease deadline. It selects due rows in producing-position/identity order. A final permitted claim remains claimed before its deadline; a later competing claim may exhaust it at or after expiry. ACK accepts the current claimed fence. Already acknowledged rows are idempotent for any positive fence under this API. ACK has no `now` input: the oracle does not invent automatic clock-based revocation in the absence of a competing claim.

`outbox_lease_case()` and the retained native public consumer establish a real original defect: a competing poll before expiry exhausted the final in-flight attempt and made its legitimate ACK stale. The minimal repair restricts claimed-row exhaustion to `lease_until <= now`, retaining exhaustion of bounded pending rows. The focused native regression covers attempt caps one/two, just-before/equal/after expiry, unrelated due work, stale positive and zero fences, and repeated ACKs.

Original/fixed native sources, commands, source hashes and output are retained under `findings/stage4-outbox-final-lease/`. The broad discovery checker keeps the deadline contract rather than adapting to the defect. Original native evidence showed the old failure and the same consumer passed the isolated repaired SQL. A discovered cross-worktree shared-Cargo-target `Fresh` reuse problem requires fresh dedicated-target replication for final source/binary attribution; successful Cargo plus source hashes alone is insufficient when that reuse is possible. Parent owns that stronger final qualification and executable retention.

## Typed persistence interactions

The `TypedOwners` operation is a bounded real interaction wave, not a fake domain store. It mints/acquires a logical lease through the actual reducer, commits via `LeaseCommitRequest`, compares the entire namespace-103 canonical state against an independently constructed known mint/acquire encoding, verifies domain request-digest binding, replays the exact acquisition, rejects a fresh but stale state CAS, verifies failed typed append invalidation, closes and reopens and checks both historical revisions and event count.

The sibling authority campaign supplies `approval::durable_approval_wave()`: real credential-registry install, Ed25519-backed approval authentication, actual `ApprovalCommitRequest`, exact commit replay, independently parsed request/action/phase/registry bindings, commit-time rejection of a stale opaque registry, and real reopen/historical state checks. See that campaign's contract for its signed-input model and limitations. Typed public restore APIs do not exist for every aggregate; durable exact historical rows are not claimed to be full typed restart/reconstruction.

## Bounds, metrics and sensitivity

At most 96 requested operations, four aggregate IDs, four saved observation slots, short event/state bytes and small outbox attempt caps keep histories cheap. Typed and multi-aggregate batch waves open their own actual database because their namespaces/records have different truth models; their internal commit/retry/failure/reopen interactions are explicitly counted. No multi-GiB representation-ceiling allocation is used. Metrics distinguish fresh/external commits, exact/conflicting retries, current/stale observations, every rejection class, real reopen, claims/ACKs, full-state observations, two-aggregate atomic boundaries and typed owner interactions. Final evidence must gate meaningful interactions, not generated case count alone.

`calibration/stage4-journal.patch` removes ordinary append's replay-generation invalidation in the real owner. The fixed witness observes, appends, then attempts guarded continuation; the immediately checked saved observation already exposes the defect. The same operation combination is common in the broad generator. This is a proposed deliberate mutation, never applied to production by this worker.

## Explicit gaps

This target does not qualify every journal family/application table, maximum representational sizes, state-history chunk boundaries, arbitrary malformed on-disk SQL rows, authority-epoch/credential cryptography exhaustively, every outbox delivery router, process-kill cuts inside SQLite commit, backups, power loss, multithreaded liveness or every OS/filesystem. SQLite locking and injected statement rollback are concrete bounded cuts; they are not substituted for those gaps. Artifacts, projections, other authority reducers and migration coordination have separate Stage 4 targets.
