# Peritus 0.1.10

This release repairs upgrades from older hosted-provider configuration, makes retained runs
recoverable when their original provider disappears, and improves the terminal's read display.
It is developed on `develop`, merged into `main`, and tagged `v0.1.10`.

- Launch after an upgrade without the generated-configuration content collision. Exact historical
  generated formats migrate to a new immutable generation while saved choices and prior files
  remain intact. Interrupted publication can finish on retry.
- Preserve the actual provider failure through admission, retries and handoff recovery, keeping
  recovery controls available instead of reporting a misleading identifier or empty-reply error.
- Use `/provider` to select replacement providers for an existing conversation. Arrows and Enter
  select, Tab changes role, and explicit forms such as `/provider reviewer 2` work too. Providers
  and models persist together on the same run. Selection affects future turns and does not itself
  resume work or replace an outstanding provider request.
- Change an existing model through `peritus providers` using the saved credential reference.
  Explicit connection testing and credential replacement remain separate choices; manual model
  selection stays available when discovery is unavailable.
- Recover specific long OpenCode planning replies with control characters, omitted optional empty
  tool calls or an exact duplicated trailing fragment. Plain-prose recovery excludes tool fields,
  container openers, tags and DSML markers. Tool proposals remain inert until normal host admission.
- Read actual saved-context entry text and metadata, including fragment and unfamiliar record
  data, with accurate null-query labels.
- See compact previews of long file, skill and context reads. `/details` expands the complete
  result; repeat it or press Esc to collapse. Very long individual lines also receive a preview.
  Short reads, errors, command results and edit diffs retain their ordinary full presentation.

Provider replacement uses the additive negotiated `app.provider-selection` protocol feature.
Existing model-only message encodings retain their meaning. Install the complete release package
so the client, TUI and daemon advance together.

The completed [configuration-upgrade campaign](../testing/configuration-upgrade-real-2026-10-21.md)
and [open-items campaign](../testing/open-items-real-2026-10-22.md) supply the behavioral evidence.
They include 43 configuration scenarios, 96 parser inputs with six strict rejection boundaries,
140 context-entry shapes, actual daemon admission/retry, six saved-key settings flows, three
fresh retained-run recovery campaigns, real official Codex requests, and native read expansion
at three terminal widths. Markdown, Unicode long lines, short files and missing-file errors
were also exercised through an actual provider and the native TUI.

This release reuses that evidence; no unit, mock, formal-verification, or repository qualification
suites were run. New paid Zen/Go inference was not exercised. The OpenCode omitted-array/prose
branches and duplicate-reply recovery include source-review boundaries described in the report;
the contributor's scripted-vendor cases are not presented as live inference. The separate macOS
real-testing issue remains unchanged. Release packaging targets all six native OS/architecture
packages and actual installation, offline terminal startup, client exit and daemon shutdown on
the four Unix builders.

Rust and WebUI metadata advance together to 0.1.10; external dependency pins remain unchanged.
Deep Research remains separately distributed through the module market with the same wire contract.
