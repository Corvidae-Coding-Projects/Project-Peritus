# Peritus 0.1.6

This patch corrects all four confirmed OpenCode parser and trace-reader findings recorded in
v0.1.5. The intended release source is `develop` merged into `main`, tagged `v0.1.6`.

- DSML parameter bodies preserve literal text. Only structural markers at parser boundaries are
  recognized; competing JSON/fenced preludes and duplicate nested JSON keys are rejected before
  publishing inert host tool proposals. Existing declaration, selection and count checks remain.
- Trace inspection retains one selected record and one output representation. Extension filtering
  skips unrelated payloads from their headers, and output is spooled in the normal Peritus cache
  before publication, retaining complete success/error documents without whole-trace RAM growth.
  The system temporary directory is not used for this spool because it can be RAM-backed.
- Trace encoding, run storage and other provider adapters are unchanged. The collecting public
  read API remains available, while streaming consumers use the new snapshot reader.

[Real-interface evidence](../testing/opencode-parser-trace-real-2026-10-20.md) records 108 production
public-provider wire replays, including 24 generated inputs, and ten actual CLI scenario groups with
24 before/after RSS measurements. A roughly 64 MiB trace's JSON-output peak dropped from about
342 MiB to 18 MiB. Sparse 10 GiB filtering, corrupted/torn traces, output storage failure,
system-temporary-directory independence and actual append/reopen behavior passed.

The provider's external vendor is a deterministic wire fixture for the recorded failures; no live
Zen/Go inference is claimed. The CLI and public reader were operated directly on Linux. Native
packages are built on all six release hosts, with actual installation/offline terminal startup on
the four Unix hosts. No unit, formal-verification or qualification suite is used.

All Rust and WebUI version metadata is synchronized to 0.1.6. Existing external dependency versions
remain unchanged; the CLI adds a direct edge to the already-locked `tempfile` library. Output spool
disk usage scales with the selected output and is removed after success or failure. Peak process
memory scales with the largest selected record, not the total trace. Deep Research remains a
separate module with an unchanged wire contract.
