# Peritus 0.1.5

Prepared from `develop` for a release PR to `main`. This includes PRs #136–#140 and
source-reuse implementation commit `675bf8165`. Planned release tag: `v0.1.5`.
This document records release preparation; it does not establish that a tag, native package,
or published release exists.

## Changes

- Reuse already-visible workspace source ranges and restore omitted pages from the existing
  durable role archive. Deliver missing intervals with exact Unicode byte/line coverage.
- Preserve task progress through retries, reconstruction and source changes while retaining
  current permissions, file-version checks and independent reviewer evidence.
- Expose private retained run traces locally with `peritus runs trace`, list trace identities,
  copy run IDs in the TUI, and retain useful rejected OpenCode replies.
- Improve OpenCode envelope recovery and retry narration. Reject Windows OpenCode runtimes
  reached through WSL interop and probe the OS credential store before asking for a key.
- Reject Windows directory junctions before writing native release archives.

## Evidence reused

Behavioral source changes were built and operated through real interfaces before the release
version bump. No unit tests, formal verification, repository verification or qualification suite
is used for this release preparation. External Cargo and npm dependencies remain unchanged.

The version bump was built offline with one build job and a 2.5 GiB memory ceiling;
the resulting client and daemon both report `0.1.5` through `--version`.

- [Workspace evidence reuse](../testing/read-reuse-real-2026-10-20.md): 20 actual API scenarios,
  48 seeded range requests, fresh-process recovery and two accepted live official-provider runs.
  A deliberate repeated read returned zero source bytes and the agent proceeded to deliver
  a working CLI. Both generated CLIs passed independent command-line checks.
- [OpenCode diagnostic and envelope recovery](../testing/opencode-rejected-turn-diagnostic-real-2026-10-20.md):
  retained trace analysis, real trace CLI operations and explicitly identified scripted provider
  replays. These are bounded observations, not proof that every malformed reply is safe.
- [WSL runtime discovery](../testing/opencode-wsl-interop-real-testing-2026-10-20.md) and
  [credential-store setup](../testing/credential-store-wsl-real-2026-10-20.md): actual terminal
  setup, vendor discovery, unavailable-store guidance and disposable credential removal.
- Windows junction replay is retained in `packaging/replay_archive_junctions.py`; this Linux
  release preparation does not claim a native Windows execution of that replay.

## Known issues retained from review

These are confirmed review findings in merged changes, separate from the source-reuse fix:

- OpenCode DSML normalization can alter literal argument text containing its special marker.
- The DSML fallback accepts a complete JSON envelope followed by a competing calls block.
- JSON-valued DSML parameters silently collapse duplicate keys before canonical validation.
- `peritus runs trace` buffers the complete trace and payload copies, including when filtering
  for extensions. A 16 MiB fixture peaked near 66 MiB RSS normally and 48 MiB with the filter.
  This is eager memory growth, not demonstrated leakage or an observed OOM.

The parser cases were reproduced directly against unchanged production modules during the
pre-release review. Host permissions still apply. These findings are not reported as resolved.

## Publication and compatibility

Source branch: `develop`. Target: `main`. After merge, the native release workflow can be
dispatched for the annotated `v0.1.5` tag to build Linux, macOS and Windows x86-64/ARM64
packages. Native package publication remains a separate step; no generated assets are checked in.

Run/context journal formats are unchanged. New source-range metadata is carried in ordinary
tool observations; older observations refresh conservatively. Independent role archives and
current access checks remain separate from reuse. The native Deep Research module remains
separately distributed and its wire compatibility contract is unchanged.
