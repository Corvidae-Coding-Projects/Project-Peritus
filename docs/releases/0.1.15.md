# Peritus 0.1.15

Peritus now offers **ChatGPT direct OAuth (preview)** in provider settings. It signs in through
the browser, owns an independent protected registration, renews tokens automatically, and sends
requests directly to OpenAI's public Responses endpoint using authorized ChatGPT plan allowance.
The existing Codex account route remains available and saved provider selections are preserved.

The direct route discovers the account's current model catalog and uses stateless conversation
and tool-result replay, including opaque reasoning state. Peritus continues to validate and
execute every host tool under current authority. Output allowance is advisory per request;
this route introduces no task-wide token budget. Protected credentials never enter generated
daemon configuration, model input, or diagnostics. Changing models preserves saved registrations;
explicit sign-out owns local token removal and attempted remote revocation.

New steering and questions now supersede a pending provider request, including after public text
starts streaming. The developer loop returns to current input assembly, retains observed usage,
and settles the host request reservation. After-operation pause semantics remain unchanged.
Local cancellation cannot guarantee that a remote provider stops computation or billing.

Actual Linux qualification used browser consent and `gpt-6.1-sol`, a nine-model live catalog,
generation and function/result continuation, a sequential two-file read plan, native Python
verification, and coding delivery through independent review. A final clean replay reached
Achieved with all 11 requests settled. Streaming steering triggered a replacement request in
0.124 seconds and the requested answer in 7.966 seconds. Two processes renewed the same
naturally expiring registration successfully, preserving identity and owner-only storage.

Live streams exposed zero-based provider sequences, absent Content-Type on valid SSE, metadata
and unsequenced errors, and tool arguments provided entirely in the final event. These forms are
handled with bounded parsing and unchanged host validation. Partial argument contradictions still
fail. The final clean coding replay exercised two final-only argument calls and round-tripped
all 1405 normalized envelopes, including 11 native zero sequences. Dynamic inspection-plan
arguments use non-strict remote generation while retaining host validation of every child.

The [design ledger](../../.design/openai-chatgpt-oauth.md) and
[real-interface reproducers](../testing/reproducers/chatgpt-oauth/README.md) preserve qualification
boundaries and discovered failures. A command-only negative scope probe executed its command
but could not qualify an empty WorkspaceChanges candidate; it is not reported as successful
delivery. Windows OAuth runtime and ACL behavior, remote revocation, reauthorization,
multiple-account switching, and other advertised models/modalities are not behaviorally qualified.

Release packaging covers six native archives for Linux, macOS, and Windows on x86-64 and ARM64.
Same-tag jobs assemble payloads and provenance, operate Unix offline startup, and exercise Windows
source installation with unusable compiler wrappers. Those observations are retained by the
release workflow separately from OAuth verification. No unit, mock, formal-verification, or
repository qualification suites are part of this release workflow.
