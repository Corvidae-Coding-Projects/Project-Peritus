# Peritus 0.1.7

This release bundles skills from one canonical source and improves run-state isolation, restart
cost, replay reuse, and native-plugin diagnostics. The release source is `develop` merged into
`main`, tagged `v0.1.7`.

- Every skill directory containing a `SKILL.md` under `skills/` is bundled automatically, together
  with its resources. Real-testing is included there; future skills need no handwritten Rust
  registration. Host execution and permission ownership remain unchanged.
- Per-run writer gates and immutable published views keep durable updates from monopolizing the
  shared registry. Readers share the metadata map and historical payload handles.
- Validated conversation replay is reused across readback and reconnect. Host commits retain
  unaffected entries, external database commits invalidate cached observations, and corrupted
  records are rejected. Cache retention limits affect reuse, not allowed task or history size.
- Disposable run indexes defer full history and continuation hydration until selection. Missing,
  stale, and corrupt indexes fall back to authoritative records. Selected state still validates
  controls, digests, and lineage; command-owner recovery remains active at startup. Repaired
  historical state can be retried in the same daemon process.
- Unchanged continuations and stored artifacts are shared instead of repeatedly serialized and
  synced. Lightweight client helpers, workspace operations, trace decoding, and native-plugin
  components now live with their architectural owners; existing compatibility exports remain.
- Native plugins continuously drain stderr into a bounded diagnostic tail. Failed and timed-out
  children are reaped, and public errors retain the terminal-safe causal tail and exit status
  even after large stderr floods.

Completed evidence is recorded in the [bundled-skills campaign](../testing/bundled-skills-real-2026-10-20.md),
[structural runtime campaign](../testing/structural-runtime-real-2026-10-20.md), and
[runtime performance review](../testing/structural-runtime-performance-2026-10-20.md).
The campaigns include 56 actual terminal scenarios, 28 CLI/launcher/shutdown cases, 256 concurrent
run updates, cache invalidation and corruption recovery, eight copied historical-run restarts,
ten candidate-identity states, 791 trace frames, and native-plugin success and failure behavior.
The configured provider route was exercised locally without inference; live provider latency
is not inferred from these results.

On the recorded copied history, warm startup dropped from 182 ms to 30 ms, ready RSS from
61.4 MiB to 28.0 MiB, and logical reads from 18.1 MB to 0.59 MB. Median repeated metadata queries
dropped from 0.231 ms to 0.015 ms. First selected-history access took 75–78 ms instead of 5 ms:
the work is deferred until needed. An 8,000-query, 16-second replay recorded six cold replays,
7,994 hits, and RSS leveling near 30 MiB. These measurements describe the recorded workload;
they do not establish a multi-hour soak or absence of memory leaks.

Selected historical payloads remain resident after first use, initial hydration is synchronous,
and small conversation projections still clone a full cached record. These are remaining
performance opportunities. Existing durable state stays authoritative and readable. Deep
Research remains a separately distributed module with the same wire contract.

All Rust and WebUI version metadata is synchronized to 0.1.7; external dependency pins are
unchanged. Release packages are built on six native hosts, with installation and offline terminal
startup exercised on the four Unix hosts. No unit, formal-verification, or repository qualification
suite is part of this release workflow.
