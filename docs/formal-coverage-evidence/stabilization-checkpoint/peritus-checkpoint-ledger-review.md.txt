## Correctness findings

1. `RequirementLedger::extract_preimage` now binds every `Err` to an input-defined
   `extraction_error` predicate. The predicate encodes the executable order exactly: empty or
   oversized collection first; then, for each draft, the adjacent identity pair before that
   draft's span, ordinal, typed shape, and paths; alternative topology last.
2. Prefix predicates select the earliest failing draft and earliest bad path pair. An earlier valid
   prefix is required before a witness can describe the first error, so a later failure cannot
   satisfy the contract in place of the actual earlier one.
3. Every modeled error fixes all four stored `ObligationError` fields. Collection and path bounds
   bind exact `expected` and `actual` values with no requirement identity. Requirement pair, span,
   and ordinal errors bind the current requirement identity with no numeric values. Shape, path
   order, and alternative errors are exact plain errors with no hidden identity or numeric payload.
4. `ObligationSpec::validate` has exactly the modeled plain `RequirementShapeMismatch` error for
   request/response schema direction disagreement. `PathMention::spec_validation_error` exposes
   the already verified size-first and first-pair contract so ledger admission can use it.
5. The ordinary public `RequirementLedger::extract` is unchanged and calls `extract_preimage`
   before canonical encoding and SHA-256. An extraction error is propagated unchanged; hashing runs
   only after success. The post-validation builder is proved infallible under the validated input
   predicate.
6. Ordinary executable behavior is preserved. The only runtime-shaped rewrite replaces two `?`
   expressions returning `Result<(), ObligationError>` with explicit `if let Err(error)` returns;
   the success values are unit and the functions have no side effects. Other source changes are
   specifications, proof assertions, visibility needed for specification unfolding, or tests.
7. Focused public tests appropriately exercise collection-first handling, interleaved earlier-draft
   versus later-pair handling, pair-before-current-span behavior, span/shape/path/alternative order,
   path-size-before-order behavior, successful canonical and empty path collections, and the
   relevant error payload fields. No stub, TODO, unsafe block, assumption, admit, external body, or
   new lint escape appears in the patch.
