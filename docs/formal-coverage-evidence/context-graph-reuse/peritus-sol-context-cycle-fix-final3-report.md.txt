## Defect and repair

The independently reviewed original481 implementation repeatedly scanned all source nodes and their dependency arrays while searching for each removable node. On a canonical ascending chain where node `i` depends on `i-1`, the production `ContextGraph::new` path regressed from 20.18x at 64 nodes to 310.03x at 1024 nodes against prior55; the measured 2048-node frozen run took 8.94 seconds.

The repair maintains one exact count per target node: the number of not-yet-removed source nodes that directly depend on it. Initialization and removal follow actual dependency edges and use the constructor-proved canonical lookup. A target is removable exactly when it is present and its count is zero. Selection still scans target indices in the original order, so the canonical elimination order and exact residual diagnostic remain unchanged.

The executable count initialization and decrement functions are connected to a mathematical remaining-dependent-count model. The proof establishes:

- initial counts equal the exact all-present remaining-dependent counts;
- every admitted dependency resolves to one canonical target;
- canonical metadata makes each source-to-target dependency contribution unique;
- removing a source decrements exactly its direct targets, without underflow;
- every maintained count continues to equal the exact remaining-dependent count;
- zero count is equivalent to absence of a remaining dependent;
- first zero-count selection is the original first-removable selection;
- the existing finite elimination certificate, semantic acyclicity iff, and first residual diagnostic contracts are preserved.

No public executable precondition, rejection guard, alternate verifier-only implementation, assumption, admit, axiom, `external_body`, or lint/checker suppression was added. The only new executable state is the dependent-count vector and scalar removed count; the prior runtime removal-order vector was removed because it existed only to mirror the ghost proof trace.
