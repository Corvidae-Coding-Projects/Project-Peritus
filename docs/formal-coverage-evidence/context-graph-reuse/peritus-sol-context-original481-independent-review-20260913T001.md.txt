## Confirmed production performance defect

The new `first_removable` examines candidate nodes and, for each candidate, `first_remaining_dependent` scans every source node and its dependency list. The elimination loop repeats that nested search once per removed node. A valid sparse ascending chain with canonical IDs and node `i` depending on `i-1` makes the highest remaining ID removable first and repeatedly drives the costly scan.

I reproduced the defect using `/tmp/peritus-sol-context-chain-probe.rs` (SHA-256 `1bb9471714555906f07e2cb5eb3dd3c4d5a763c4e05ac276d9c93cdd24adcc4d`). Node construction and the input `Vec` clone occur outside the timer; the timer covers only the actual `ContextGraph::new`. Each series has one warm-up. Exact prior and frozen source manifests were checked before the runs, and the release builds used separate never-used disk targets.
