## Implemented behavior and proof boundary

The actual selection path now folds global and per-worker reservation quantities once into canonical resource vectors and then checks request dimensions with indexed lookup. If a sum or union cannot be represented by the bounded `ResourceVector`, it uses the prior exact per-reservation fallback. This preserves the capacity decision for overflow cases rather than converting aggregation failure into admission or rejection.

The production-executed Verus functions prove:

- indexed lookup returns the exact present quantity or zero for an absent kind;
- canonical addition returns exact per-kind sums and ordered union entries, reports arithmetic overflow exactly, and retains overflow-before-dimension-limit priority;
- the existing dimension guard runs before constructing the bounded `ResourceVector`, so two valid disjoint input vectors may correctly return `LimitExceeded` without asserting a false intermediate invariant;
- subtraction returns exact differences, detects underflow first, treats quantity zero as the existing absent-dimension sentinel, and returns `ExactZero` exactly when the difference sequence is empty;
- global and worker aggregate folds equal the actual reservation quantities whenever representable;
- aggregate and fallback capacity checks both refine the same operational global/worker predicates.

`ResourceVector::checked_add` and `checked_subtract` are ordinary wrappers around these production-called verified kernels. Their enum-to-error mappings and exact strings were source-reviewed and exercised by tests, but the public wrappers themselves do not carry Verus result contracts. The proof does not establish allocator, wall-clock, compiler-optimization, or asymptotic performance properties.

No `assume`, `admit`, axiom, external body, verifier substitute, executable precondition, new runtime admission guard, or lint allowance was added in these paths.
