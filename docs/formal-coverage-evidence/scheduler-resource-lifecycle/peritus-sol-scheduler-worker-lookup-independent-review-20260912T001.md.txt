## Behavior and proof review

`SchedulerState::worker_index` contains the same binary-search loop previously embedded in the
public `worker` getter. Its postcondition proves every returned index is in bounds and identifies
the requested worker. The public `worker` method now calls that helper and reconstructs its prior
exact `Some` contract. Its signature, visibility, `must_use` behavior, returned reference, and
`None` behavior are unchanged.

`set_worker_phase` now calls `worker_index` first. On a hit it passes the proved in-bounds matching
index to the existing verified `set_worker_phase_at` mutation. That mutation retains the same
phase update, worker-sequence relation, reservation invariant/readiness preservation, and binding,
work, reservation, and used-dispatch frames already reviewed at checkpoint316.

On binary miss, the prior complete linear loop still runs. This preserves the unconditional
private-helper result contract even though the current proof does not establish binary-search
`None` completeness. For canonical sorted unique production state, an existing worker follows the
binary path. The public SetWorkerAvailable, DrainWorker, RemoveWorker, and LoseWorker routes first
perform the existing public worker lookup, so unknown-worker errors return before the mutator and
retained workers use the binary hit path. No error kind, diagnostic string, precedence, event
payload, or public state-transition API changed.

The correction report's phrase that runtime behavior is preserved for *arbitrary* unvalidated
decoded state is slightly broader than the code guarantees: with duplicate matching worker IDs,
the binary search may update a different duplicate than the old first-match linear scan. The
formal private-helper contract still holds, and canonical public state rejects duplicate worker
IDs, so this wording issue is not a production blocker.

No executable guard, public precondition, assumption, proof escape, lint suppression, or adjacent
contract expansion was added. The correction does not claim a formal asymptotic theorem. It does
restore binary-first lookup on normal retained-worker updates; the fallback remains linear only
after a binary miss.
