# Generated configuration upgrade

The original v0.1.9 binary must reproduce `generated daemon configuration generation 21 has
different content` when a hosted route's otherwise matching generated file lacks the new
`discover_model_limits = true` line. Updated bootstrap must publish the current format in
generation 22, preserve all earlier files and durable choices, and use generation 22 again
on subsequent preparation. Current configurations must not advance their generation.

The replay drives real immutable files, the public launcher API, actual native CLI processes,
PTY terminal interaction, and the actual daemon. Fixtures use inert credential references;
the campaign never requests provider inference or reads real credentials. It disables automatic
browser dependency downloads in isolated test processes because browser installation is outside
this configuration contract.

Build the actual program with bounded resources, then link the consumer against that exact cohort:

```sh
peritus_upgrade_root="$(mktemp -d)"
CARGO_TARGET_DIR="$peritus_upgrade_root/target" CARGO_BUILD_JOBS=1 CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_DEV_OPT_LEVEL=0 \
  cargo build --locked -p peritus-cli -p peritus-daemon --message-format=json > "$peritus_upgrade_root/build.jsonl"
python3 docs/testing/reproducers/configuration-upgrade/build.py \
  --cargo-output "$peritus_upgrade_root/build.jsonl" --output "$peritus_upgrade_root/consumer"
python3 docs/testing/reproducers/configuration-upgrade/replay.py \
  --consumer "$peritus_upgrade_root/consumer" \
  --binary "$peritus_upgrade_root/target/debug/peritus" \
  --baseline /path/to/unpacked-v0.1.9/bin/peritus \
  --output "$peritus_upgrade_root/evidence"
```

Use the platform's published v0.1.9 executable as the baseline. The driver currently targets
Linux: its generated fixture layout uses XDG roots and its native terminal driver uses Unix
PTYs. No platform-specific production code changes are involved. It requires only Python's
standard library, the built application, and its normal local dependencies.

Seed `271821` generates twelve provider subsets and historical-format combinations. Explicit
cases cover all seven hosted services, mixed account/direct routes, offline mode, old OpenCode
capabilities, removed timeouts, old folder catalogs, unchanged configurations, unrelated-edit
rejection, private file permissions, backed-up config regeneration, interrupted publication,
four concurrent preparations, and actual terminal startup/shutdown/reopen.

The input transformations describe earlier generated formats. The independent checker requires
current discovery settings, exact preservation of durable choices and all previous files,
one new generation only when required, exact freshly generated bytes, private permissions,
and real terminal attachment. Unrecognized edits must fail without publishing replacement state.
The driver retains its observed baseline failure, terminal output, concrete generated cases,
and binary identities in the output directory; disposable state and owned daemons are cleaned up.
