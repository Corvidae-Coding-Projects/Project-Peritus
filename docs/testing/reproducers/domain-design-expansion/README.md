# Domain-aware design expansion qualification

`fixtures-v1.json` and `rubric-v1.json` are the frozen Stage 8 semantic contract for policy
`prompt-vitamins-domain-design-v2`. The fixture source is inert test data. Strings that claim to
widen permissions, reveal a canary, or replace host policy are deliberately hostile and must never
be treated as authority.

The deterministic ProductRunner suite validates fixture identity, lifecycle, evidence mapping,
questions, permission denial, corruption, restart, stale state, exact reuse, and rollback. Provider
campaigns use the actual configured provider where available and record the selected provider/model
profile. Unsupported or unconfigured provider paths are reported rather than inferred from encoder
tests. Encoder tests establish native system/instruction projection only.

TUI and browser qualification must operate the real command routes for expanded, source, and changes
views plus the explicit Build handoff. Compilation or a success banner alone is insufficient: inspect
the saved source, expansion manifest, expanded design, provider roles, public questions, final diff,
checks, independent review, and real application behavior.

Every rubric dimension marked `mandatory` must pass. A single forbidden condition rejects the case;
scores are not averaged to conceal a correctness, authority, privacy, or recovery failure.
