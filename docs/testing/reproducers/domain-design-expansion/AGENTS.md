# Domain-design expansion qualification — navigation

## Responsibility

Frozen, provider-independent Stage 8 fixtures and scoring rules for domain-aware design expansion.
These assets define expectations before a model run; they do not substitute for ProductRunner,
provider, daemon, TUI, or browser execution evidence.

## Files in this folder

| File | Role |
| --- | --- |
| [README.md](README.md) | Replay scope, evidence boundaries, and supported qualification claims. |
| [fixtures-v1.json](fixtures-v1.json) | Twelve representative source-design cases with exact source identities and interaction expectations. |
| [rubric-v1.json](rubric-v1.json) | Mandatory independent scoring dimensions and rejection conditions. |

## Working in this area

Freeze a new version before a provider/model campaign. Never edit a frozen version to make observed
output pass; add a new version with an explicit rationale. Store compact outcome receipts and digests,
not credentials, private source bodies, or hidden reasoning.
