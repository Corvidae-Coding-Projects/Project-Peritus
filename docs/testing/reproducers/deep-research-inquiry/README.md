# Independent inquiry: actual-interface consumers

The [campaign record](../../deep-research-inquiry-real-2026-10-17.md) separates native
integrity/recovery, live research operation and substantive quality under the
[frozen rubric](../../research-quality-rubric-v2.md). None substitutes for another.

`native-replay.py` and `declared-position-replay.py` run the actual framed native executable
using a completed legacy episode's retained observations. Pass the native executable, that
episode's module `state` directory and a fresh owned output path explicitly:

```sh
python3 native-replay.py --native /path/to/peritus-deep-research \
  --archive-state /path/to/disposable-legacy-module/state --output /tmp/new-native-replay
python3 declared-position-replay.py --native /path/to/peritus-deep-research \
  --archive-state /path/to/disposable-legacy-module/state --output /tmp/new-position-replay
```

The replayed archive is the earlier rejected neutral-topic campaign, with 21 candidates
and a first-party candidate for question one. It is an explicit prerequisite, not generated
evidence. Use a copy of retained disposable campaign state, never live user state. Existing
output paths are refused. The consumers locate the shared native framing consumer relative
to this directory. Only framing helpers are loaded; its old generated-case loop is not run.

The first replay exercises conservative legacy approval, plan identity, source-role constraints,
open inquiry persistence, follow-up, actual-query gap validation and early rejection. The second
exercises full native handoffs, qualified first-party evidence for a narrowly stated-position
question, fresh-process exact report and checked Design attachment. They make no new HTTP,
model-inference or substantive deep-research quality claim. Fixture mutations occur only in
the fresh output; original candidate bytes are compared where copied state is used.

`audit-readback.py LIVE_OUTPUT_ROOT` independently compares actual live-driver terminal
readbacks with the exact report/review/check records, complete report pages, evidence quote,
inquiry, fresh-daemon origins, ordinary chat marker and unchanged workspace canary. It expects
the artifacts described in the campaign record and never grants semantic acceptance.

## Real long-timeout recovery

On Linux, `build-provider-retry.py FRESH_BUILD_ROOT` builds the public developer-loop consumer
with two Cargo workers. Run:

```sh
python3 provider-retry.py --binary /path/to/peritus-real-provider-retry \
  --output /tmp/new-owned-provider-fault
```

The actual official Codex client must already be authenticated. The coordinator SIGSTOPs only
the first `exec` process parented by this consumer, preserving PID/start identity for cleanup.
Authentication probes, later attempts and other processes are left alone. The real transport
deadline expires after 125 seconds, exceeding the former 120-second total retry horizon.
Acceptance requires a recorded retry after that actual elapsed interval, subsequent real
inference returning the exact marker, zero application tools and cleanup of the stopped child.
No provider, failure event or clock is mocked. The coordinator's five-minute observation
deadline is separate from product policy. This probe makes a real provider request.

## Focused delivery replay

`delivery-replay.py` takes the same explicit arguments as the declared-position replay. It
operates a fresh real native episode using archived observations: one vetted passage informs
two questions, an unused candidate remains unassessed, optional history is explicitly deferred,
and the report stays partial for that question. Human `finish` disables new discovery and
followups across process restart. The exact report still traverses source checks and review.
This is a behavioral contract replay, not a new factual endorsement of the historical topic.

The native replay also compares full and compact admission selection over the same actual
records, verifies exact IDs and selected detail, and records serialized size/page counts.
The delivery replay checks that synthesis's compact view still excludes unassessed evidence.

## Continuous native controls and historical readers

`continuous-replay.py --native BINARY --archive-state COMPLETED_REAL_STATE --output FRESH_DIR`
uses a completed real report with the controversy workflow (six committed stages). It runs
the actual executable through normal delivery, stable checkpoint acknowledgement, stale
ack rejection, restart, Unicode steering, pause, multiple continuing cycles, and return to
normal termination. The native handoffs reuse valid retained outputs; they are not fresh
model research. A second version changes only title/citation ordering through the real report
revision/check/review tools, with references renumbered and unchanged source observations.
The reader assertions confirm that old page continuations and numbered evidence stay bound
to the old digest after the newer checked version exists. This controlled variant is never
delivered as the user's new research report.

`attribution-friction-replay.py --binary BINARY --fixture RETAINED_FAILURE_FIXTURE
--version 1.4.0 --expect-fixed --output FRESH_DIR` consumes the preserved exact arguments,
candidate/read receipts and seed state from the two observed failed admission calls. It
checks useful offset diagnosis, qualified/unclear attribution and fresh-process custody,
while retaining rejection of bad quotations and unqualified attribution. Original fixture
state is not invoked.

`audit-readback.py ROOT --prefix controversy-` selects the six-stage report exports while
retaining the original older campaign format. `--allow-host-upgrade` is explicit when a
readback deliberately spans different host builds; exact client/daemon hashes remain in
the receipt. Neither option grants substantive research acceptance.
