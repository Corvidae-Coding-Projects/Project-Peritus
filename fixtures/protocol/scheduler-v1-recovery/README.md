# Historical scheduler recovery frames

## Folder guide

Version-one scheduler recovery inputs grouped into benign replay, loss, and retry cases; digests bind the retained bytes.

Use [AGENTS.md](AGENTS.md) for file-level responsibilities, child modules, parent context, and nearby implementation owners.

### Local files

| File | Role |

| [README.md](README.md) | Human guide and operating/background notes for this folder; AGENTS.md provides the local navigation map. |
| [SHA256SUMS](SHA256SUMS) | Recorded SHA-256 inventory for neighboring retained input/artifact files; keep bytes and digest entries consistent. |

### Subfolders

| Folder | Role / next waypoint |
| --- | --- |
| [benign/](benign/AGENTS.md) | Retained scheduler checkpoint and event bytes for benign recovery/replay. |
| [loss/](loss/AGENTS.md) | Retained scheduler checkpoint and event bytes representing loss during recovery. |
| [retry/](retry/AGENTS.md) | Retained scheduler checkpoint and event bytes for interrupted work eligible for retry. |

These bytes were produced by the unchanged schema-1 scheduler at protected-base
commit `a41113d1389c3d8fc77a00cc562cb9a5bcb7adc8`, in a detached source checkout.
They were not regenerated by the schema-2 implementation.

Each history has queue limit 1 and active reservation limit 1. It starts the
scheduler, registers a worker, admits A with two attempts, dispatches and starts A,
then admits B into the waiting queue. The final event respectively completes A,
fails A retryably, or loses A's worker. The retry and loss checkpoints contain two
waiting items: the original reducer accepts them but its original checkpoint
decoder rejects them. Even the benign history's admission of B would be rejected
by schema-2 admission, which is why replay must retain the explicit old semantics.

Command/event suffixes are fixture identities, in sequence order 01,03,04,05,06,07,08.
`SHA256SUMS` covers all 45 immutable frames. Tests compare decoded/re-encoded bytes,
deterministic transitions and replay, and the complete final checkpoint. Production
code must continue decoding these frames without rewriting their bytes or digests.

Capture evidence is retained in the GAP-03 workspace under
`target/gap3-evidence/62-base-history-export.log` and
`62-legacy-fixture-export.rs.txt`.
